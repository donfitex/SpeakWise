# Security reporting

Do not disclose credentials, learner data, or exploitable details in public issues. Use the repository's GitHub private vulnerability reporting feature if enabled. If unavailable, open a minimal issue requesting a private reporting channel without sensitive details; maintainers must establish that channel before receiving a report.

The application is under development and is not ready for real learner data. Production release requires authorization/ownership tests, CSRF and secure-session protections, rate limits, private audio storage and expiry, dependency checks, and an operational incident/deletion process. This document makes no security certification or legal compliance claim.
