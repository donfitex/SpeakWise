# SpeakWise on Render

This is a single-instance advisory pilot deployment. Render runs a Docker web
service containing Caddy, Gunicorn, one Celery worker, and one scheduler under
Supervisor. A managed Redis-compatible Key Value instance supplies the broker
and cache. Use the existing Neon PostgreSQL database through DATABASE_URL.

The API and worker must share private audio files. Render disks cannot be shared
between separate services, so these processes intentionally share one container
and a disk at /var/data. Do not scale this service horizontally. A future split
into services requires a private object storage backend. Raw audio is never
served by Caddy; the existing processing and scheduled cleanup remove it.
The persistent disk makes deploys interrupt service; this is a pilot architecture.

## Required values

Set these in Render's initial Blueprint form or its Environment settings:

- DATABASE_URL: your Neon PostgreSQL connection string, including TLS settings.
- EMAIL_HOST: your SMTP server.
- EMAIL_HOST_USER and EMAIL_HOST_PASSWORD: SMTP credentials from your email provider.
- DEFAULT_FROM_EMAIL: a verified sender address.
- EMAIL_PORT defaults to 587 with STARTTLS. Adjust for your SMTP provider.

DJANGO_SECRET_KEY is generated by Render. Redis connection details are wired by
the Blueprint. No AI credential is required: speech transcription is disabled
and typed lessons work without an AI provider. Do not put secrets in GitHub or
VITE_* variables. Optional paid transcription would require a real provider key,
not a randomly generated string.

## Deploy and verify

Commit these files to the branch used by your Blueprint. In Render, create a
Blueprint from the repository and review the resource plan and current prices.
This configuration uses paid web compute, a disk, and Key Value. Prices and
schema require validation against the current Render platform before applying.

The Docker build installs locked dependencies and builds the frontend.
Startup checks production configuration, migrates the database, and seeds the
fictional sample curriculum (SEED_DEMO=true). Set SEED_DEMO=false after the initial
deployment. Back up an existing database before migrations. This configuration
is intended for a new dedicated pilot database.

Render terminates HTTPS; Caddy serves the frontend and proxies the API on the
same origin, preserving session and CSRF cookies. The onrender.com hostname is
added to Django's allowed hosts and trusted origins automatically. For a custom
domain, also set DJANGO_ALLOWED_HOSTS and CSRF_TRUSTED_ORIGINS explicitly.

After deploy, verify HTTPS /api/v1/health/, registration/login, placement, a typed
lesson and saved progress. Verify SMTP password-reset delivery and worker
check_speech_worker. Review worker/scheduler logs without learner payloads.
Create staff users through an interactive Django createsuperuser command in the
Render shell; no shared administrator password is generated.

The repository's existing educational review, speech calibration, and backup/
restore release gates still apply. A live URL alone does not establish those
checks. If a supervised process fails, inspect the service logs immediately.
